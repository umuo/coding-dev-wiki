# 完整代码智能体运行时

## 目标与验收

保留通用 OpenAI 兼容模型接口、Git/ZIP/本地导入、固定网页、源码追溯、停止/继续；用完整代码智能体执行分析，应用不实现模型工具循环，不强制串行目录分区。优先生成概述、主要功能和架构，用户通过源码引用及问答深入细节。

验收用真实 OpenCode 二进制连接仅本机的假模型：探索后能生成有效结果、引用必须对应真实返回行、结果校验失败在同一会话修正一次、停止断开正在执行的模型请求、进程重启后恢复同一会话、不继承个人插件/配置/无关密钥。真实大仓库的速度与质量必须另做真实模型验收，不能由单元测试推断。

## 选型与 spike

选用 [OpenCode](https://opencode.ai/v1/docs/server/) 1.19.5 的 headless HTTP API；与该版本官方 SDK 类型核对，并实际启动二进制验证。复用完整工具执行、原生会话持久化、读取/检索、待办与上下文压缩，不复制其 Agent Loop。Python 服务继续负责产品工作流，无需改成 Node.js。

比较了当前 2.2.7 与 1.19.5：2.x 的 HTTP API 标记为 experimental，协议与 v1 不同；本版锁定仍发布的 1.x 二进制及稳定路由。固定版本 `format: json_schema` 能返回结果，但持久化消息回读存在兼容错误，因此不使用该路径；普通最终 JSON 输出已通过完整读取、取消与重启恢复验证。应用使用 Pydantic 校验 Schema 和已读引用，不实现工具参数解析或循环。

旧实现中，一个 16 文件分区读取到 37 个文件，51 次读取，最后输入 92316 token，8192 输出全部用于思考且没有有效回答。这是旧分区范围与预算策略的真实反例。新实现取消该执行路径；不声称更换运行时就能让任意模型达到 Codex / Antigravity 的质量。

## 安装与配置

```bash
python -m app.runtime.install
python -m app.dev
```

安装器从官方 npm 平台包下载固定版本，校验 SHA-512，只提取二进制，不执行 npm 安装脚本。本机默认安装到 `.data/bin/opencode`；Docker 构建自动安装到 `/usr/local/bin/opencode`。生产 PATH 中也可以提供该固定版本，或通过 `WIKI_OPENCODE_BIN` 指定路径。空值采用默认位置，再查 PATH。缺失或版本不匹配时明确失败，不自动换回旧分析器。

现有 `WIKI_LLM_BASE_URL`、`WIKI_LLM_API_KEY`、`WIKI_LLM_MODEL`、`WIKI_LLM_CONTEXT_TOKENS` 继续使用，不新增需要用户手动调节的模型预算项。默认总窗口 128000 时，工作输入最多 32000，输出预算 32000；不同窗口自动推导并预留余量。供应商不支持该输出上限时仍会明确报错，应使用其真实可用模型规格。

## 执行与恢复

每个任务都有独立 OpenCode 数据目录和 localhost 服务，随机认证密码，服务只在任务期间运行。基于同一不可变索引生成 repo/ 只读文件；代码探索和原生压缩由运行时负责。只开放源码读取、目录检索与待办；禁止 Shell、编辑、外部目录、联网工具、插件和项目运行配置。工作区自身建立干净 Git 边界，不使用导入仓库的 Git 元数据。

应用订阅 OpenCode 原生 SSE 即时采集动作和工具结果，每 10 秒补充等待心跳；不显示隐藏思考内容。每轮最多等待 300 秒；模型/HTTP 超时在同一会话自动重试两次，间隔 2 秒、5 秒，连续原生接口重试也设有限制；停止时先中断会话，再关闭隔离服务及进程组，保留数据库。检查点 v3 保存会话 ID、实际读取范围、用量和已验证草稿；恢复同一源码与原生会话。旧检查点完整保存在 legacy 字段，不把旧的大段工具消息导入新运行时。

最终 JSON 通过 Schema、路径、行号及实际读取内容比对后才发布。校验失败只请求修正一次，不重新扫描整个仓库。源码导航仍包含全部索引文件；分析结果明确披露未读取数量，不把可追溯误写成已穷尽理解全部代码。

## 实时动作与超时重试

需求：浏览器实时显示原生工具的等待、执行、完成/失败状态、模型请求、压缩与重试；刷新恢复历史，断线后重连并补齐，不把隐藏思考、源码全文或供应商原始错误转发到网页。

复用官方 `/event` SSE 和 httpx-sse 解码器，提交请求前完成订阅；事件按会话过滤和动作 ID 去重，工具完成事件用于立即验证读取范围。现有任务 SSE 传递持久化动作事件。消息快照用于最终校验与断流补齐，不再每秒轮询完整历史。

仅模型/HTTP 请求超时自动重试两次，间隔 2 秒、5 秒，复用原生会话，不重复附加整份提示。认证、输出超限与校验错误不进入超时重试；停止会取消请求与重试等待。应用级重试与原生接口重试都显示在动作区，并分别设限。

验收覆盖：原生动作在模型请求结束前显示；开始/结束更新同一动作；刷新与 Last-Event-ID 恢复；断流重连和会话隔离；敏感内容过滤；超时成功恢复、重试耗尽与等待期间停止；真实 OpenCode + 本地假模型的浏览器链路。
