# 使用说明

## 最小运行

本地开发运行 `python -m app.dev`，自动加载项目根目录 `.env`；显式导出的环境变量优先，修改后重启。生产启动不自动加载 `.env`。

从 README 创建虚拟环境、安装依赖，启动 `uvicorn app.api:app --host 127.0.0.1 --port 8080`。

1. 访问首页，输入公开 Git 仓库 URL，或选择 ZIP。
2. 配置模型后选择 Agent 分析；没有模型可选择清楚标注的结构预览。
3. 处理页面显示阶段与日志，刷新不会丢失已持久化事件。
4. 完成后点击“进入分析结果”。从概览看架构，点击功能查看跨文件实现步骤；点击片段引用打开完整文件。
5. 按 Cmd/Ctrl K 搜索；选择全仓文本可查找实际代码；行号可跳转、点击可复制链接。
6. “项目问答”支持多轮对话，引用可跳转。对话只保留在本次页面内存，刷新清空。

## 配置

| 环境变量 | 默认值 / 空值行为 | 含义 |
| --- | --- | --- |
| WIKI_DATA_DIR | `.data` | 相对启动目录的数据路径，保存任务、上传包、源码和结果；应备份或挂载持久卷 |
| WIKI_LLM_BASE_URL | `https://api.openai.com/v1` | OpenAI Chat Completions 兼容接口根地址，包含 `/v1`（若服务需要） |
| WIKI_LLM_API_KEY | 空 | 服务端密钥；空时禁止 Agent 分析和问答 |
| WIKI_LLM_MODEL | 空 | 支持工具调用的模型名；空时仅允许结构预览 |
| WIKI_ACCESS_TOKEN | 空 | 空时不鉴权，仅适合本机可信环境；配置后首页登录并用 HttpOnly Cookie 访问 |
| WIKI_GIT_HOSTS | `github.com,gitlab.com,bitbucket.org` | 逗号分隔的允许主机，需 DNS 解析为公开 IP；不接受 URL 凭据 |

| WIKI_GIT_ALLOW_FAKE_IP | `0` | 仅管理员确认使用 Fake-IP DNS 代理时设为 `1`，允许已在主机列表中的站点解析到 `198.18.0.0/15`；不放开其他私有地址 |

模型配置统一在服务端，修改后重启。本地开发启动器自动读取项目根目录 `.env`，其他启动方式需通过进程环境配置。源码会发送到该模型服务，请使用适合项目隐私要求的服务。模型不支持工具调用、返回无效引用或调用超限时任务会失败，不自动假装分析成功。

## 错误与恢复

失败任务点击重新分析创建新任务。Git 不可访问时可改用 ZIP。上传失败的 ZIP 需要重新上传。服务重启会将排队中和执行中的任务标记为失败；已完成结果仍可访问。重新分析不会覆盖旧快照。

部署只使用一个 Uvicorn worker，不启用多个副本。任务执行池最多同时处理两项；后续生产化可替换为外部队列。反向代理需关闭 SSE 缓冲并允许长连接。持有实例访问令牌的人可查看实例内所有项目，本版不提供成员隔离。

## 本地开发模式

运行 `python -m app.dev`，打开本机页面并展开“开发者模式 · 本地项目目录”。输入服务所在机器的绝对项目路径，沿用上方分析方式。原仓库只读，结果保存为快照；重新分析读取最新内容。

`WIKI_ENV` 默认为 `production`，`WIKI_DEV_MODE` 默认为 `0`，只有分别为 `development` 和 `1` 才启用。启动器固定监听回环地址，关闭代理转发头解析。开发接口也拒绝远程、转发或跨源请求。生产环境无路由及 HTML/脚本入口；生产镜像不包含开发专属文件。

## 分析失败后继续

失败的 Agent 任务显示“继续分析”：保持原任务 ID，复用源码索引、Pydantic AI 消息和已读取区间，从检查点继续；已完成模块会跳过，当前模块保留自己的工具历史，后续模块使用独立上下文。每次手动继续重新分配有界调用预算。运行中、已完成或结构预览任务不能继续，重复点击不会创建并发执行器。

“重新分析”仍会创建新任务并重新读取最新源码。继续分析则使用先前保存的源码快照，原仓库变化不会混入本次解释。生产模式仍拒绝恢复本地目录任务。

旧版本失败任务没有保存检查点，首次继续会明确记录“无法恢复之前的 Agent 上下文”，重新获取/读取源码后分析。之后会保存检查点。模型输出格式或引用校验反复失败时，日志显示错误原因及最近校验反馈；继续不保证模型一定能纠正输出。

## 模型上下文窗口

只需配置 `WIKI_LLM_CONTEXT_TOKENS`，单位为 token，默认 `128000`，最小 `8192`。本地写入项目根目录 `.env`，修改后重启 `python -m app.dev`；生产环境通过环境变量或 Compose 注入。请填写模型服务实际允许的总上下文窗口（输入与输出合计），不是字符数。

```dotenv
WIKI_LLM_CONTEXT_TOKENS=128000
```

系统自动分配单次输出上限（窗口的四分之一，最多 8192 token），预留协议与估算余量，剩余用于输入；目录分页、源码读取、搜索与记录大小随预算缩放，无需另配 `max_tokens`。功能、模块和关系逐条保存，最终只输出简短概述，避免整份报告触及输出上限。

使用官方 Pydantic AI Harness 的规划、记忆及滑动窗口压缩组件，并在每次请求前校验上下文预算。项目按模块分段分析，最终独立汇总；模块摘要、待查任务、工作笔记和已保存结果独立保留，可用工具查回。压缩保留工具调用/结果配对。较早的源码内容被压缩后，Agent 可重新读取。tiktoken 对已知模型使用对应编码，未知兼容模型用 cl100k_base 估算并预留余量；并非所有服务的精确 tokenizer。获取词表失败时退回 UTF-8 字节数的保守估算。实际服务端 token 统计和模型输出能力仍以服务商为准，增大配置不能扩展模型本身的真实窗口。

旧整份输出检查点会迁移：保留已读源码，舍弃被截断的最终输出调用，改用逐条生成。新版继续只补齐未完成条目，完整结果仍从服务端装配；不会把旧的引用校验反馈误作为当前截断错误的原因。

## 运行状态与停止

任务详情显示排队中、正在运行、停止中、已停止、失败或已完成；最近项目列表自动刷新状态。排队和运行任务可点击“停止分析”。后端取消排队项或当前异步模型请求；Git、ZIP 和源码扫描在安全边界检查停止信号。操作未退出时显示“停止中”，结束并保存检查点后才显示“已停止”，不把请求停止冒充已停止。

停止保留源码快照和已保存的 Agent 记录，Agent 任务可点击“继续分析”；结构预览任务可重新分析。已结束任务不能被停止，停止中的任务不能提前继续。完成与停止竞争时由数据库状态原子判定，停止不会被后续日志覆盖成运行或完成。

## 工具参数格式容错

模型的工具参数必须是 JSON 对象。Pydantic AI 校验前会用 json-repair 处理普通 JSON 语法错误，并仅在 schema 要求对象/数组时解码被二次编码的嵌套 JSON。修复后仍必须通过字段、类型、非空说明及源码引用校验，不能补造路径或行号。

检测到 DSML/XML 协议混入损坏参数时，不猜测业务字段，要求模型按工具 schema 重新提交。格式失败的调用及对应错误结果从下一次模型输入中移除，保留合法调用配对、已读范围和独立保存结果，避免模仿错误格式。工具纠错预算固定为 4 次，仍受总请求预算限制；持续异常仍会停止并保留检查点，可手动继续，不会无限重试。
