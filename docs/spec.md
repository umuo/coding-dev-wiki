# MVP 需求与验收

## 用户已确认的目标

独立部署 Web 系统。用户输入 Git 地址或上传 ZIP，页面显示真实处理日志及阶段进度；完成后点击进入结果页。保留原 code-viewer 的功能导航和实现链路阅读体验，分析目录不能绑定任何特定仓库。

## 范围

1. Git / ZIP → 有界后台任务 → SSE 进度 → 持久化结果 → 点击跳转。
2. LLM Agent 自动分析；Agent 循环必须复用现成实现；生产分析接入完整 OpenCode 运行时，Python 服务通过 headless API 管理会话。
3. 固定 UI，动态生成功能、模块、概述、架构与引用。
4. 保留链路片段、函数聚焦、完整文件、目录、符号、搜索、引用导航和分享链接。
5. 扩展项目问答、首页描述和架构图。
6. 出错可解释、可重试，结果绑定分析时的源码版本。

## 验收规则

- 两个不同结构的仓库无需改产品代码或手工功能目录即可导入并浏览。
- ZIP 和实际公开 Git URL 均可完成导入；日志真实反映实际阶段，100% 仅在结果写入后出现。
- Agent 通过框架调用只读工具，产出经过 schema 验证的内容。引用路径和行号有效，而且对应区间必须已被 Agent 阅读。
- 功能 → 实现步骤 → 片段 → 完整文件能够连续访问，行号和链接对应同一快照。
- 刷新任务页面后可重放日志；完成后显示结果入口；失败显示原因并可创建重试任务。
- 问答调用同一快照的源码工具，回答附引用，证据不足时明确说明。
- 桌面三栏、窄屏可切换导航，无源码或模型文本被作为 HTML 执行。

## 边界

MVP 是单实例、单可信工作区，不含用户级多租户权限。只读源码，不安装或执行导入项目，不支持私有 Git 凭据（用 ZIP）。支持常见 UTF-8 源码及文档，限制 ZIP 50 MiB、展开 150 MiB、分析文本 40 MiB / 2000 文件 / 单文件 512 KiB。未知格式、敏感文件名及依赖产物跳过并报告；任意语言不保证同等语义精度。

结构预览是显式诊断模式：不调用模型，不宣称业务理解。静态分析不保证运行时路径真实发生，也不保证解释完全正确。文件引用可校验，结论语义需要读者复核。首次概览采用下述独立预算；覆盖不足会在分析边界显示。

首版手动全量重新分析；旧结果不随磁盘变化而漂移。不包含增量分析、自动提交监听或跨仓库问答。

## 本地开发导入

仅同时设置 `WIKI_ENV=development` 与 `WIKI_DEV_MODE=1` 时注册本地目录入口。仅本机回环连接、localhost/回环 Host、同源且没有转发标记的请求可显示和使用。默认生产模式不注册路由、不注入 HTML/脚本；生产 Docker 构建排除启动器、开发路由和前端专属资源。

本地目录必须为存在且可读的绝对目录，不能是文件或文件系统根。使用现有源码过滤与分析限制，原项目只读；分析结果绑定读取时的快照。重新分析会读取目录最新内容；生产环境不能重试历史本地任务。

验收：本地目录导入成功并进入结果页，原文件无修改；目录失效报错；修改后重试生成新快照；切到生产模式后 HTML、脚本、OpenAPI、直接 POST 和历史任务重试均无可用本地入口。

## 失败后的人工恢复

Agent 异常时保留源码快照、OpenCode 原生会话及已读区间，并显示具体失败原因。人工继续复用同一任务和快照，不重新获取源码，恢复过程由原生运行时执行，不重建旧分区对话。服务中断遗留的未完成工具调用标记为中断，不能伪造成功。旧版本无检查点的任务明确提示重新读取。接口具有鉴权、失败状态的原子抢占和本地来源生产隔离。

## 模型窗口自适应

唯一用户预算配置为 `WIKI_LLM_CONTEXT_TOKENS`，默认 128000。生产运行时自动分配输入、输出和压缩预留，压缩阈值必须大于零。检查点保留原生会话、已读证据及已验证结果。历史 Pydantic 分析器的逐条保存仅用于旧检查点回归。连续分页读取可联合支持引用，有未读间隙时仍拒绝。

## 可观察运行状态和人工停止

详情展示实时状态和停止按钮；列表自动刷新。停止状态流为 queued/running → stopping → stopped，只有执行退出且检查点写入完成后才能宣告 stopped。排队项取消 Future；运行中的模型调用取消 asyncio Task 并走框架 finally 保存；导入与扫描协作停止。停止不应被进度事件或结果落盘覆盖为完成。已停止的 Agent 可使用原任务继续，仍遵循鉴权和本地来源生产隔离。


## 快速概览与按需深入

默认 Agent 导入只生成快速概览，聚焦用途、使用入口、1–4 个主要功能、主要业务链路及简要架构。保留全部索引文件的浏览和搜索能力，引用仍必须对应同一快照的真实已读区间；不承诺已理解每个文件。

首次探索最多 90 秒、8 轮模型步骤、24 次工具调用或 12 个读取路径，任一预算先到即中断探索，保留已取得证据，并通过原生消息级工具开关进入只整理阶段。原生事件有异步延迟，单次并行批次可能略超出调用/路径上限；不宣称逐工具同步拦截。整理和一次校验修正共享 90 秒，不因自动重试重置阶段预算；分析总保护上限 210 秒，导入/本地索引耗时另计。超时不是响应速度承诺。

没有有效源码证据时明确失败并允许手动继续，不冒充业务理解；有证据时整理可核验的有限概览，未知内容写入分析边界。校验失败只修正现有证据，不再次扩大全仓探索。完成概览即开放结果，无自动后台深度扫描。点击首页或功能页“按需深入了解”打开预填问题，用户发送后问答 Agent 才检索同一快照；直接查看源码不调用模型。旧结果仍可浏览。

验收：预算耗尽会关闭后续读取并成功整理；无证据不发布结果；复用会话时旧消息不消耗新一轮预算；停止/继续保持有效；不同上下文窗口的压缩阈值均大于零；浏览器可完成导入→概览→功能→预填深入问题→引用源码。验证用本地假模型，不以此声称真实供应商速度达标。
