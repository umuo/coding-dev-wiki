# 历史方案：模块化 Harness

本页记录旧实现。2026-11-12 真实任务验证发现探索范围失控、上下文膨胀和思考预算耗尽；生产分析入口已替换为[完整 OpenCode 运行时](runtime.md)。以下离线测试不代表真实分析性能通过。

目标：大型仓库不依赖一份不断增长的对话；模块分析完成即保存摘要、结果和状态，中断后只继续未完成模块。UI、不可变快照、证据校验、停止/继续行为沿用现有实现。

## 选型与兼容性 spike

选用 MIT 的 [Pydantic AI Harness](https://github.com/pydantic/pydantic-ai-harness/tree/v0.36.0)，锁定 harness 0.36.0 / Pydantic AI 2.44.0。已在隔离 Python 环境运行原有 89 项离线测试，通过。兼容 core 1.x 的 harness 0.3.0 只有 Code Mode，不具备本次所需组件。新版规划、记忆和压缩 API 已核对发布 wheel 源码。

复用官方 Planning / InMemoryPlanStore、Memory / InMemoryStore、SlidingWindowCompaction；应用仅实现快照适配、模块分区和阶段调度，不实现新的模型工具循环。相较 [Deep Agents](https://github.com/langchain-ai/deepagents)，该方案保留已验证的 Pydantic AI 引用校验、工具与取消语义，减少迁移面。代价是升级 core 主版本，且固定 harness 版本需要后续主动升级。

## 行为与边界

- 按索引路径确定模块，所有文件恰好属于一个模块，最多 12 个分区；小项目直接分析，较大项目先逐模块分析，再独立汇总。
- 每个模块使用独立消息历史。可跨模块读取依赖；完成模块的摘要通过工作记忆和按需工具供后续阶段读取。
- 检查点仍使用 v2，新增 workflow、plan、memory 字段；旧检查点保留所有已保存记录和已读范围，按新计划补充分析，原文件不被删除。
- 计划、笔记与功能/架构记录独立保存；压缩仅影响模型输入，不清除证据或已完成模块。官方压缩负责工具调用配对，精确预算适配层保留工具 schema、工作记忆和输出预留。
- 记忆属于当前任务，不能跨项目读取；不提供 Shell、源码写入或执行工具。模型笔记不能替代 read_file 引用验证。
- 只需配置上下文窗口；模块数量、工具输出、记忆注入和请求上限自动推导。静态分区不等于语义架构，未读取文件数量继续在结果中披露。

## 验收

离线验证模块历史隔离、失败后跳过完成模块、持久化笔记在压缩和恢复后可查询、旧检查点恢复、全部路径覆盖、小窗口预算、引用校验、停止取消、兼容 HTTP provider；运行完整 pytest。浏览器验证既有停止/继续流程。用户要求暂不调用真实模型，真实仓库分析质量留待用户更换模型后验证。
